# 志愿者联络保障

本项目用于整理社区服务运营数据。`fixtures/` 保存本地合成源记录，各表字段和业务时序约定见 `DATA.md`。没有线上服务或真实个人信息。

使用 Python 3.11 验证资料结构：

```sh
python3 -m unittest discover -s tests -v
```

## 换班前联络保障分析

`handoff/` 在源记录之上做联络保障分析，输出换班前报告：

```sh
python3 -m handoff            # 使用 fixtures/
python3 -m handoff 其它目录    # 指定源记录目录
```

报告分七节：联络路线认定、独立备援与成对断点、约定的单点中断情景、
演练证据分级、真实换班事件与责任归属、新增联络安排比较、按班次复盘。

### 认定口径

- 消息在一条联络段上的占用为 `[开始, 开始+minutes)`，开始及完成均须在
  发送班次、接收班次和通路时段内（左闭右开）；内容权限须被每段边和
  两端岗位覆盖；同一人员同一时刻只承接一项。
- 签收须严格早于截止时刻（"须在 deadline 前签收"）。
- 两条路线共用电话 channel 或值班关口 gateway 即不算独立备援；
  时间不重叠的排班不能连在一起。
- 同一情景（正常排班或某一约定的单点失效）下所有服务共用同一份排班
  与占用事实；保留承诺优先、截止早者优先；赶不上截止的服务转入人工
  联络清单，不再占用联络能力。不用整体平均连通率证明某个班次。
- 演练证据分已知 / 可能 / 未知 / 已知失败：只有 confirmed 算交接成功，
  missing 只给可能确认区间、不自动算失败；按日/夜班（19:00 分界）与
  权限级别分别认定，白班成功试拨不替夜班签收，高权限记录可覆盖低权限
  内容，不同授权不能凑成一次成功。
- 换班以值班台可见时间（received）推进：备用接手未确认前原归属不变；
  提议未决期间占用该人员候命时段，不再划给别的链；提议撤回后迟到的
  确认不成立；原路线失联标"待恢复"，不悄然改派也已失效的路；恢复后
  不再依赖断点的服务放回，赶不上截止的留在人工联络清单。
- 新增联络安排（options）：同一试拨名额每时段仅一份（窗口重叠即互斥）；
  人员改全程候命会消耗其岗位已承诺的到场服务；保留承诺的既有归属
  不被新安排占用。
